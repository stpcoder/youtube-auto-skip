# Architecture and release boundaries

## General blocking

The MV3 manifest loads static DNR rules from `filters/network.json`. Sources, licenses, hashes, counts and conversion limits are preserved in `filters/provenance.json` and `filters/sources/`. Visual rules and official generic/element/specific-hide exceptions are in `cosmetic.json` and `cosmetic-policy.json`. Compatibility rules are authored in `general/site-rules.json`; selected sites use compatibility-only visual rules and network exemptions to preserve content.

Plain unconditional host blocks are packed into `requestDomains` groups of at most 500 instead of silently losing coverage at the converter's rule limit. The current snapshots retain 46,469 hosts in 93 groups within 7,203 total rules. Conditional/path rules and exceptions stay in the converter; plain `$badfilter` overrides remove grouped hosts as well. A future quota overflow fails the build. `filters/sources/focus.txt` is an independently authored set of verified provider, creative and banner-template signatures, not copied upstream code. It does not block shared image CDNs or publisher navigation. Unsupported converter syntax is still reported; this is not a complete uBlock engine.

`build-general.mjs` produces independent `main-bundle.js`, `content-bundle.js` and `worker-bundle.js`. Policy/data dependencies are lexical bindings inside each bundle. MAIN and ISOLATED do not depend on one another's globals or duplicate asset-path initialization. Root `background.js` imports the worker bundle. Edit component sources, then rebuild; generated runtime files are committed for installation without Node.js.

Cosmetics use `chrome.scripting.insertCSS`, observe page changes, and report readiness/errors through `YAS_GENERAL_STATUS`. Popup handling checks `window.open`, new-window anchor clicks and popup-tab navigation. Preferences remain in `chrome.storage.local`; parent-domain pause covers subdomains. These switches do not disable YouTube protection.

## YouTube and Safari

Chrome MAIN scripts process supported response ad fields, install an anti-adblock guard, set up bounded initial empty-buffer recovery and monitor ad events. Responses include recognized initial assignments, fetch/XHR and a narrowly recognized streaming frame. `early.js` tries player commands and enabled skip controls. `content.js` can request input assistance; the worker validates senders, refreshes coordinates, attaches/detaches the debugger and cancels for vanished documents.

Recovery excludes live, Shorts, playlists, seeking and already-playing states. Reload attempts and observed `playing` events are separate outcomes. Hiding the Korean interruption notice does not cure buffering; other errors remain visible. Changed formats, server-stitched ads and server-imposed waits are not guaranteed to be handled.

Safari development source is Focus 1.3.3; the previous public ZIP remains 1.0.0. Its fixed YouTube bundle runs directly in MAIN at `document_start` (Safari 18+, iOS target 26+), with request hooks before optional media UI. The isolated bootstrap verifies that startup and only injects fallback files if missing. Mobile/MWEB startup tags the first player/get_watch request with `eAFgAQ`; actual fetch/XHR POST hooks also cover cached serialization and missing optional playback fields. HTML-embedded initial responses get one immediate empty-player request when its API is ready, without duplicating an already tagged first request or resetting decoded/paused content. Failure recovery restores the original once. Chrome retains conditional empty-buffer recovery. The build bundles shared cosmetic/popup data and adapts network rules to Safari DNR, excluding main-frame blocking and retaining YouTube exclusions. General filtering requires HTTP/HTTPS site permissions; Chrome debugger input is omitted. A compact floating SVG toolbar appears automatically on watch pages, without starting media actions; its three controls retain 44px touch targets. PiP requires a user action/native confirmation, with actual presentation state reconciled on foreground return. Background mode retains the original video; native continuous playback remains separately unvalidated. The optional onboarding Swift Package and assembled extension can be exported for integration into another app, subject to GPL compatibility. [Safari guide](SAFARI.en.md)

`siteFeatures` stores per-host boolean `providers`, `banners` and `popups` preferences; absent values default to true. More-specific host preferences override inherited ones. Legacy `globalEnabled` and `disabledSites` remain master controls. Provider-off creates only a network allow exception, banner-off removes USER cosmetic CSS, and popup-off disables both MAIN URL interception and the new-tab watcher. Child provider opt-ins are excluded from parent network exceptions. Category writes preserve unrelated hosts and master settings. The Safari popup exposes these controls; shared Chrome runtime policy supports the same data without changing its existing popup UI.

Physical MWEB inspection found `get_watch` sent as a native Request with gzip-compressed JSON before the watch URL changes. The targeted hook clones its body, decodes gzip, tags the destination `playerRequest` while retaining `watchNextRequest`, and recompresses only changed JSON. Request headers/options/abort signals and native fetch responses are preserved. A native fetch rejection cannot issue a second request. Diagnostics distinguish serialization transforms, transport transforms, compressed requests and HTML-response reloads; a playing event records an observation rather than proving all-ad coverage.

URL-classified advertising image links can promote their single-link `.hd_pops_con` parent notice to a verified ad slot. The reusable notice backdrop is hidden only when it contains verified advertising notices and no unmarked normal notice remains. This fixes an empty touch shield after normal notices are closed without disabling every modal or intercepting ordinary page clicks. Attribute-based selectors avoid invalid nested `:has()` syntax. Installed browser checks cover visible normal notices, closing the final normal notice, and hit-testing through the empty advertising backdrop.

## Packaging and repository structure

The root remains directly installable. Moving runtime files into another source directory would disrupt existing unpacked installations. Refactoring therefore concentrates on shared package utilities and generated bundles. `scripts/lib/package-utils.mjs` resolves manifest dependencies, rejects paths outside the package and writes ZIPs with stable timestamps/order. `build:release` rebuilds both targets, checks assets/locales/provenance and produces separate Chrome runtime and Safari development ZIPs with SHA-256 checksums, license notices and a tagged-source link.

Node.js 22+ is the prerequisite for ZIP generation on macOS/Linux/Windows; no external ZIP executable, Python or Xcode is used. Native Safari project generation requires Mac/Xcode. `build:filters` downloads lists; `--offline` rebuilds recorded sources. Neither is required to install a Chrome ZIP.

`verify` runs bundle generation, Node tests and package checks. `test:browser` uses disposable Chromium profiles, extension APIs and local fixtures. It does not establish real YouTube or country/account-specific ad coverage. [Validation](VALIDATION.md)

## Permissions and privacy

General blocking needs HTTP/HTTPS access, DNR and scripting. Local storage holds settings; tabs/webNavigation support site controls and popup handling. Chrome `debugger` enables skip-button input assistance and may trigger a browser control notification. No external browsing-history analytics endpoint is present in the source. Filter snapshots do not refresh automatically.

## Development dependency advisories

The pinned AdGuard converter brings advisories through `js-yaml` and `sprintf-js`, including a high-severity advisory on `js-yaml` 3.x. `npm audit fix` does not resolve this tree. Its scriptlet dependency calls `safeLoad`, so overriding the major version needs compatibility work. These libraries are build tooling, not executable runtime dependencies in either ZIP. `fflate` creates ZIPs and Playwright supplies optional browser checks; neither is included in the extension. Converter upgrades and compatibility review remain open.
